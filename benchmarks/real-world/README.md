# Real-world bitcode suites

Whole-program LLVM bitcode used by the control-dependence evaluation
(`scripts/control_dependence/evaluate_control_dependence.py`). These are
performance inputs, not correctness tests, and are not part of the CTest graph.

| Directory    | Programs | Tracked in git | Size   |
| ------------ | -------: | -------------- | -----: |
| `SPEC2006/`  |       18 | yes            |  ~40 MB |
| `coreutils/` |      109 | **no** (ignored) |  ~24 MB |
| `open/`      |       24 | **no** (ignored) | ~403 MB |

`coreutils/` and `open/` total roughly 427 MB, so they are listed in
`.gitignore` rather than committed. Recreate them locally before running the
evaluation; the harness discovers whatever is present, so a partial suite still
runs and simply reports fewer subjects.

## Rebuilding the suites

Both suites are whole-program bitcode produced with the same LLVM 14 toolchain
used everywhere else in this repository. The standard route is
[`wllvm`](https://github.com/travitch/whole-program-llvm) (or `gllvm`):

```bash
export LLVM_COMPILER=clang
CC=wllvm CFLAGS="-g -O3" ./configure && make
extract-bc <built-binary> -o <name>.bc
```

- **`coreutils/`** — one bitcode file per GNU Coreutils utility, named after the
  installed binary (`cat.bc`, `ls.bc`, ..., including `[.bc` for `test`).
- **`open/`** — mature open-source applications and libraries: SQLite, PHP
  (`php`, `php-cgi`, `phpdbg`), Tmux, Lua (`lua`, `luac`), cURL, Ninja, Brotli,
  Qt `moc`, thttpd, vsftpd, bftpd, and several LLVM tools (`llvm-ml`,
  `llvm-mt`, `llvm-config`, `FileCheck`).

must not be redistributed.

## Note on the evaluation

Every subject in these suites has an **empty** DOD relation: across 211,036
functions and roughly 1.1 million binary decisions, no function yields a
non-empty order relation, because clang emits essentially reducible CFGs and
DOD is empty on reducible graphs. Lowering multiway switches
(`--lower-switch`, on by default) adds about 11% more binary decisions and does
not change that outcome. The non-empty case is covered instead by
`benchmarks/synthetic/closure_k*.ll`, generated by
`scripts/control_dependence/synthetic_family.py --generate-closure-suite`.
